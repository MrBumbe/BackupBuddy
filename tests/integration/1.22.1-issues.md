## ENRADSFIX-001 — Step C2 — Pip warnings in installer output (Anders only)

**Type:** ENRADSFIX  
**Step:** C2 (install gatekeeper on Anders, VM 101)  
**Observed:** The installer produced many `WARNING: Ignoring invalid distribution ~agic-wormhole` lines during the "Installing Python dependencies" phase. These did not appear on Björn or Carina (which had fresh venvs). This is caused by a partially-installed magic-wormhole package left in the venv from a previous test run that was snapshotted into `clean-ubuntu-v2`.

**Expected (INSTALL.md §3):** Clean output with only `[✓]` check lines. No pip warnings.

**Impact:** Cosmetic — the install succeeded. A real user would see alarming spam. The INSTALL.md expected output block does not mention these warnings.

**Root cause:** The `clean-ubuntu-v2` snapshot for VM 101 contains a pre-existing venv with a corrupted `magic_wormhole` package. Fresh installs (VM 102, 103) are clean.

**Fix required:** Two options:
1. Rebuild the `clean-ubuntu-v2` snapshot with a clean venv (or no venv), OR
2. Add pip cleanup step to the installer that removes invalid distributions before installing.

**Status:** Snapshot issue — not fixed inline (requires snapshot rebuild or installer change). Recorded here for follow-up.

## NOTE-001 — Step C5 — recovery_key_confirmed=true in clean-ubuntu-v2 snapshot

**Type:** NOTE  
**Step:** C5 (download recovery kit on Anders)  
**Observed:** The `onboarding_state.json` in the `clean-ubuntu-v2` snapshot already has `recovery_key_confirmed: true`. This caused the `/api/onboarding/download-key` endpoint to return 404 (it blocks download once confirmed). The recovery_kit.enc file WAS written by the cascade (236 bytes, confirmed on disk).

**Impact:** The "Download recovery-kit.enc" step of the wizard is effectively skipped in the test because the snapshot state has already confirmed the key. Not a bug — the file exists and is correct.

**Why it happened:** The `clean-ubuntu-v2` snapshot was taken after a test run where the recovery key was confirmed. The state file persisted into the snapshot.

**Resolution:** No action needed for this test. For future: consider resetting onboarding_state.json in the snapshot or including it in the factory-reset file list for A0.

## ENRADSFIX-002 — Step F1 — INSTALL.md §5a says to replace whole backup.cfg

**Type:** ENRADSFIX  
**Step:** F1 (agent install, §5a check)  
**Observed:** INSTALL.md §5a instructs the user to "Replace the file contents with the complete
example below, filling in your own values." The example includes placeholder values for `url`,
`token`, and `name` under `[gatekeeper]`. However, the installer already writes a complete
`backup.cfg` with the correct token, URL, and agent name. Replacing the whole file would
overwrite the installer-generated token, breaking the agent–gatekeeper connection.

**Expected:** The guide should instruct the user to add backup paths under `[backup]` only, not
replace the whole file.

**Root cause:** The guide was written before the installer started writing a full `backup.cfg`.

**Fix applied:** Rewrote §5a to say "Do not replace the whole file — add folders under [backup]
only" and removed the misleading full-file example block.

**Status:** Fixed in INSTALL.md.

## NOTE-003 — Step F0 — TTY detection fires late (after package install)

**Type:** NOTE  
**Step:** F0 (TTY detection test, 1.21.2A)  
**Observed:** Running `sudo bash /opt/backup-buddy/install/agent.sh` without a TTY and without
env vars produces the correct error message:
`[✗] No interactive terminal detected. To install non-interactively, use: ...`

However, the check fires inside `ask_questions()` which is called AFTER package installation,
venv creation, service user creation, and directory setup. The installer runs for 1–2 minutes
before outputting the error. The FAIL condition (`/dev/tty: No such device or address`) was NOT
produced — the fix (1.21.2A) is working correctly.

**Result:** F0 PASS — correct message produced, no /dev/tty crash. The late-firing nature is
a minor UX issue (user waits before seeing the error) but not a regression.
