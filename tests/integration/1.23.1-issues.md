ISSUE-1 | cluster/join | Partial idempotency gap: accept_join has Fix (C) for "used invite + already a member" (returns success) but has NO guard for "fresh/unused invite + already a member". When Carina (already in members table) uses a valid NEW invite code, accept_new_member raises IntegrityError (duplicate node_id) because the member row already exists. The invite IS consumed (used=1 in DB) but HTTP 400 is returned to the joiner. Expected: if node_id already in members table, skip insert, return success (and optionally consume or leave the invite unconsumed). Severity: medium

Context: join.py::accept_join Fix (C) covers only the exact retry path (same used invite + same member). It does not cover the fresh-invite + duplicate-member case, which arises in the E6 idempotency test when a new invite is generated after a cascade failure.
