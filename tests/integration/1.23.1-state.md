### L4 — Unmount tmpfs and verify successful upload

After unmounting tmpfs, the agent did NOT automatically retry on the next watcher cycle.
Root cause: `FileWatcher._queued` set retains failed-upload paths indefinitely in memory;
`_upload_worker` does not remove the path from `_queued` after a failed upload.
Recorded as ISSUE-3.

Workaround applied: `sudo systemctl restart backup-buddy-agent` to clear in-memory state.
After restart and one watcher cycle (~60s): `SUCCESS — uploaded file (209715200 bytes)`.
Catalog confirmed: `disk-guard-test.bin` (209715200 bytes) in catalog on gk-anders.

Result: **PASS** (with note: required agent restart due to ISSUE-3 — no automatic retry after failed upload).
